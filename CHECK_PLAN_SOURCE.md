# Check a saved plan against an original synthetic world

A reviewer can independently select the raw `WorldState` file that supposedly
produced a saved `towerops.world-plan.v1` report, and ask whether the report
names the **exact original input bytes**, the **same native synthetic world**,
both or neither. This is a read-only comparison of two existing files, not
another planner invocation.

```sh
python3 -B plan_world.py source-world.json > saved.plan.json
python3 -B check_plan_source.py saved.plan.json source-world.json
python3 -B check_plan_source.py saved.plan.json source-world.json --json
```

The report must already exist; neither input is changed by this checker. The
plain-text response displays the status, both identity checks, both SHA-256
pairs, recorded review clock and selected world's original synthetic
observation clock. `--json` emits the complete structured result with
`format: towerops.plan-source-binding.v1`. The pure API is
`verify_plan_source(report_raw: bytes, world_raw: bytes) -> dict`: it returns
the same structured assessment without command-line paths, I/O or clock use.

## Four distinct binding statuses

| `binding_status` | Raw bytes SHA-256 | Native world hash | Exit |
| --- | --- | --- | --- |
| `exact_bytes_and_world` | match | match | 0 |
| `same_native_world_different_bytes` | differ | match | 1 |
| `reported_bytes_but_different_world` | match | differ | 1 |
| `different_bytes_and_world` | differ | differ | 1 |

Both checks must pass for `matched: true`. A report's
`input_sha256` is only a recorded assertion until the selected original raw
file's SHA-256 is computed. The *native world hash* represents the parsed
version, observation time and aircraft data; whitespace-only reformatting
can change original file bytes without changing native world identity. Both
representations matter. A report may also record an input SHA-256 that matches
one file while internally naming an entirely different, individually valid
world; the third status exposes precisely that inconsistency. No status
silently upgrades a byte mismatch to exact-original success.

Exit **2** means an invalid argument, source/read/admission error or failed
output. Such failures print a diagnostic to stderr and do not emit a normal
binding result. The checker prepares the entire output before attempting
stdout. A failed stdout write can still leave partial bytes downstream;
consumers must check the exit code before accepting a saved result.

## Existing native admission and source custody

The checker imports and reuses the unchanged
`compare_plans._read_report/_parse_report` and
`plan_world._read_world_file/parse_world` helpers. It does not run
`review_world`, enumerate candidates, screen, plan, approve, issue
setpoints, modify synthetic traffic or access an external provider.

Report inputs are direct regular files (not symlinks or special files), at
most **4 MiB**, with strict UTF-8 JSON, duplicate-field rejection, exact
report schema, bounded numbers, internal world identity, saved advisory
body-hash checks and status consistency. Raw worlds follow the existing
**256 KiB**, **60-aircraft** and finite-number input limits, native version
and identity validation, and the original world's symlink policy. Files are
opened through the supplied operands; the checker does not scan directories
or search for the original world on its own. Both files must be explicit
paths; stdin is deliberately unsupported because two separate inputs are
required. Path strings are returned exactly as authored and are not converted
to canonical paths.

Only the supplied source file is assessed. The report's recorded review time
and the world's observed time are *synthetic seconds* and remain distinct.
Neither is replaced with wall time or used as freshness authority. Successful
hash comparison is **not** cryptographic producer authentication or a claim
that the reported policy, scenario, saved alternatives or candidate count were
actually generated by the current native planner. It does not re-evaluate the
candidate menu, certify safety, verify live aircraft or grant clearance or
actuation authority.

This consumer needs Python 3.10+ and the source checkout, but no optional
Strands agent/model/provider packages. Keep the original report and world
alongside any saved binding result if evidence custody matters.

## Qualification

Focused source and actual-process checks:

```sh
python3 -B -m unittest discover -s tests -p test_check_plan_source.py -v
python3 -O -B -m unittest discover -s tests -p test_check_plan_source.py -v
```

The suite exercises all four combinations, normal and optimized real CLI
processes from another directory, Unicode path handling, signed zero,
empty-world input, invalid/oversized/duplicate source JSON, invalid/oversized
and hash-tampered saved reports, symlink distinction, output errors and input
file preservation. These are synthetic/fixture receiving checks, not
installed-device, browser, operational or independent human qualification.

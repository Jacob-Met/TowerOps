# TowerOps / Airspace Lab

A standalone Canvas page for synthetic traffic. It advances each aircraft with the same constant-velocity projection used by `Aircraft.projected`, then runs a TypeScript browser port of `SafetyPolicy` and `AdvisoryPlanner` on every changed world. Add/perturb controls change world state; there is no animation-only traffic and no live data or model call.

## Verify against Python

From the repository root:

```bash
python tools/generate_airspace_reference.py
python tools/generate_airspace_reference.py --check
cd web/airspace
npm ci
npm test
npm run build
```

The checked-in fixture is generated by the original Python classes. Vitest compares world hashes, conflict pairs, target/setpoint selection, approval/readback state transitions, and audit hashes. It also checks that a missing acknowledgement is rejected without actuation.

## Run the browser page

From `web/airspace`, run `npm run dev`; then open the printed local URL. The demo uses only synthetic aircraft. The controller approval/readback controls are explicit fixtures, not real authority. TowerOps is not operational ATC software, aviation assurance, or real-aircraft control.

`tools/capture_airspace.py` is an optional local Chrome/Playwright check used to capture the desktop and phone states; pass `--chrome` if Chrome is not at the Raider default path.

## Preview a selected-flight edit

Open **Shape the traffic** and choose **Edit TWR419** (or the flight selected in the traffic register under **Under the hood**). The existing fields fill with that flight's position, flight level, bearing, speed and climb. Its callsign stays fixed, and traffic pauses while you edit.

**Preview edit** compares the current and edited conflict intervals without changing the world. **Apply scenario edit** replaces only that flight, advances the world version once, retains the existing decision trace, and clears previous planner proposals and approvals. This authors a synthetic scenario; run the planner on the changed world before its approval/readback flow. A scenario edit can introduce conflicts as well as remove them.

**Cancel edit** preserves the world, pending proposal and approval, and returns the builder to its previous new-flight draft. Traffic stays paused. Changing a field invalidates the preview; a changed world, policy or clock also prevents applying a stale edit. Unchanged velocity vectors retain their exact values during position or altitude edits.
